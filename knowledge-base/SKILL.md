# 知识库与记忆

本环境通过 MCP 工具连接 llm_token_hub 的知识库与记忆服务。数据按调用者账号隔离。

## 自动触发规则

**知识库 = 组织的权威事实；记忆 = 这位用户/项目的个人历史与偏好。**

必须主动检索知识库：
- 用户问“我们的/公司/项目/产品/业务/流程/规范/需求/数据”等内部事实。
- 你要在回答中声称组织约定、指标、部署方式、负责人、业务规则，但没有本会话内的可靠依据。
- 用户说“查文档/查知识库/看看资料”。
- 回答前发现关键信息可能来自内部文档，而不是通用编程或公开常识。

必须主动检索记忆：
- 用户说“上次/之前/我们说过/我提过/继续昨天/按老规矩”。
- 任务涉及用户偏好、代码风格、技术栈、汇报方式、项目命名、审批流程。
- 开始一个非琐碎的项目任务前，先用 3~6 个关键词查询一次相关记忆；不要每个回合都查。
- 知识库结果不足，但答案可能依赖这位用户或项目的历史决定。

不要检索：
- 纯通用知识、语言语法、公开 API、数学计算。
- 当前工作区代码和短上下文已经明确回答的问题。
- 用户只是闲聊或要求改一个局部错字，且没有组织/历史依赖。

## 决策顺序

1. 组织事实优先 `kb_search`；用户身份/偏好/历史约定优先 `memory_search`。
2. 两者都可能相关时，先 `memory_search` 获取任务上下文，再 `kb_search` 查权威依据。
3. 单个问题最多做两轮检索；第二轮必须换更精准的关键词或范围，不要重复同一查询。
4. KB 与记忆冲突时，以 KB 为权威事实，并把冲突告诉用户。
5. 回答内部事实时注明来源文档名；来自记忆时注明这是历史约定或用户偏好。

## 何时保存记忆

保存：
- 用户明确说“记住…”“以后都…”“我们团队的约定是…”。
- 长期偏好：称呼、技术栈选择、代码风格、汇报习惯。
- 项目约定：命名规范、部署流程、审批链、架构决策。
- 用户确认某个方案成为后续约定时，保存一句可复用结论，不要保存整段对话或完整代码。

不保存：
- 一次性任务、临时上下文、未确认方案、完整日志。
- 敏感凭据（密码、API Key、私钥）。

保存前先用核心关键词 `memory_search` 查重；已有等价记忆不要重复保存。发现冲突时，先向用户确认是否遗忘旧记忆，除非用户已明确要求替换。

## 何时导入知识库

导入：
- 用户明确说“导入/存进知识库/加入公司文档”。
- 用户要求把某个文件或当前已确认的结果沉淀为组织知识。

不导入：
- 中间过程、未确认方案、临时日志、含密钥内容。

优先导入原始文件；只有没有对应文件时才导入已确认的文本结论。

## 工具速查

| 工具 | 何时用 |
|---|---|
| `kb_list` | 首次使用知识库、确定 `kb_ids`、或导入前了解范围 |
| `kb_search(query, kb_ids?, top_k?)` | 检索组织权威事实；内部事实/业务规则/项目文档优先使用 |
| `kb_import(paths?, content?, title?, kb_ids?)` | 导入本机文件或已确认结果；先 `kb_list` 确认可写目标 |
| `memory_save(content, session_id?)` | 保存长期偏好、项目约定、已确认决策；保存前先查重 |
| `memory_search(query, limit?)` | 混合语义+关键词查找记忆；继续任务或历史偏好优先使用 |
| `memory_forget(message_id)` | 遗忘某条记忆；ID 从 list/search 获得 |
| `memory_list(limit?)` | 用户要求查看/整理最近记忆时使用 |

记忆检索是混合语义+关键词匹配：自然语言问题或 2~3 个关键词都可以；结果不确定时换更具体的说法再试一次。
